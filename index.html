Small tools for local systems, agents and Go services.

This is the index for the projects I maintain. Two are open source and installable. Two are private, so their pages describe what they do, with screenshots or a diagram, instead of linking to code.

They fit together: Desk runs on Torok, reads the market through Canary and is served by HyperServe.

Broker data and MCP · open source

Canary

A local Interactive Brokers MCP server, CLI and risk desk. It connects Claude Desktop, Claude Code, Cursor, Zed and shell workflows to account and market context from IB Gateway or TWS.

  • The Claude Desktop MCP bundle is the fastest install path.
  • Standard builds and MCP are read-only; gated broker writes need a separate opt-in trading build.
  • Useful for portfolio review, options diagnostics, scanners, breadth, gamma and regime context.

Private · investment agent

Desk

A continuously running desk for one Interactive Brokers book. It reviews the book on the market's clock, keeps evidence and decisions in durable storage, answers questions through a reviewed workflow and leaves every trade to a passkey-confirmed human step.

  • Built on Torok for durable work, Canary for broker facts and HyperServe for the console.
  • Every decision carries its sources, a reason, what would prove it wrong and an expiry.
  • A monthly model allowance with a hard ceiling. Idle time costs nothing.

Private · Go library

Torok

A Go library for agents that use tools, and for workflows written as plain Go functions. It runs the tool loop, checks typed answers and commits progress, so work resumes after a person answers or the process restarts.

  • Agents are configuration, workflows are functions, tools are ordinary Go signatures.
  • One set of limits shared by every child call, with a spend ledger that reserves before the request goes out.
  • A resident service adds an inbox, timers, memory and observers for agents that stay on.

Go HTTP server library · open source

HyperServe

A net/http-shaped Go server library. It keeps ordinary handlers, collects lifecycle, typed boundaries, security, observability and WebSocket in one module, and can expose an MCP server from the same binary when that is useful.

  • Built on the standard library, with one runtime dependency.
  • Includes middleware, graceful shutdown, static-file sandboxing, WebSocket, SSE and JSON-RPC pieces.
  • MCP support is opt-in, with Streamable HTTP and stdio sharing one handler.
